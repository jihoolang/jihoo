# 0.6 proof status and release blocker

This is a gap assessment against the [original 0.6 roadmap](roadmap.md), not a
new release policy. In particular, proving the production checker implementation
correct is **not** added as a gate. The implementation may remain trusted and
be tested against the specified rules. Counts of theorems, passing tests or PRs
are not a percentage of the required soundness result.

## Principal blocker

There is not yet one specified-Core typing judgment whose derivations establish
runtime ownership and borrow safety across the required language. Pure typing,
quantity control traces and guarded heap operations are useful existing parts,
but proving them separately does not establish their composition for arbitrary
Core programs accepted under the specified rules.

Evidence in the current code and statements:

- `CoreBridgeBetaTyping.HasType` handles the existing pure scalar/array/evidence
  and function grammar. It does not have `Buffer`, `Ref`, `Alloc`, `Lend` or
  `Free` rules and its variable lookup is unrestricted ghost-mode lookup.
- `HeapLeases.Step` requires liveness, lease authority and no active borrow at
  deallocation. Its invariant theorem cannot by itself establish that typing
  supplies those preconditions.
- `Quantity.Control` and its erasure theorem concern projected resource traces.
  They are not the full Core runtime interpretation of those traces.
- The earlier `ScopedLend` result is scalar by syntax. But `Core.infer`'s `Lend`
  rule calls `outlived`, which permits `Buffer`, `Back` and data `Ind` results as
  well as scalars. `core_lower` passes both the reader result and the original
  owner to the continuation. An owned reader result must therefore be a second
  independently accounted-for resource, not a scalar or an alias of the owner.
- `MirCallerValidation.Accepted` checks agreement of independently supplied
  source and target graphs. Its conditional theorem is not a proof that the
  general lowering function produces such a target for every typed source.

The existing direct contribution is a declarative mixed-result `Lend` rule on the
**existing Core constructor graph**, reusing the heap/lease semantics. Its
continuation typing consumes resources by their identity, clears every lexical
alias on consumption, and permits arbitrary finite allocation/free sequencing.
This same judgment now includes Lend recursively in continuations and handles
any selected capability among multiple live owners; alias/borrow authority is
proved from the lexical context. Readers can return a scalar or allocate a fresh one-cell buffer
while the original owner's lease is active. The same judgment now distinguishes
owner identities, scalar value slots and consumed names, carries the actual
scalar result through subsequent Lends, and proves bounded scalar results
together with ownership safety under explicit initial value bounds. Closing an owned-result lease transfers the new buffer and the original
owner as two distinct capabilities; a scalar result retains only the original
capability and adds its actual scalar value. Primitive step guards and safe transfer
must follow from the typing and environment invariants, not be supplied as an
assumed safe event trace or an `Accepted` certificate.

This is a direct extension for an omitted specified rule, not the full solution.
It still restricts buffer shape and reader expressions. Continuation nesting
creates sequential lease regions, not nested active-reader Lends. The remaining common
judgment must account for recursive data/field ownership, `Back`, more general
reader results and contexts, recursion, and their substitutions and runtime
interpretations. Extending syntax without those connections would not close
the principal blocker.

## Structural connection still required

The largest remaining difference is not another missing scalar test. Actual
`Core.infer` shifts dependent variable types, distinguishes runtime/erased
lookup, and `dependent_lend` substitutes the borrowed original and returned
owner into the reader/continuation before inference. Pure `Raw.Beta.HasType`
already has dependent typed substitution, while the graph ownership judgment
uses owner/scalar slots. A common proof must relate those interpretations; merely
renaming the ownership judgment `HasType` would not do so.

The open scalar computation bridge now interprets mixed lexical scalar entries
as the existing pure typing context and provides its closing substitution.
Owners and consumed names are unavailable in that context. Its generic
substitution result applies to existing open Raw terms and dependent result
types. A finite executable graph grammar retains actual scalar let binders and
realizes their computation in the existing pure reduction relation, feeding the
value into the same ownership continuation rule.

This is the first direct reuse of that pure substitution/evaluation proof at
this ownership execution boundary. Immediate owned-argument binding additionally transfers the selected capability
to a formal parameter while invalidating its earlier lexical aliases. This is
not general substitution of owned functions, Buffer/Ref dependent types or
Borrow values in the full Raw typing language.
The executable grammar is structurally terminating first-order I64 lets; there
is no assumed successful evaluation in typing. General higher-order termination,
arithmetic traps and U64/I64 distinctions cannot be inferred from this fragment.

The next runtime rule is ordinary owned application, which differs materially
from Lend. Actual `Core.infer` requires a linear lambda parameter to be used
exactly once; `uses` counts the runtime argument and any captured use of the
original owner separately. Therefore an immediate Buffer1 application cannot
simply add another usable alias as Lend does. The common judgment transfers
lexical authority to the new formal parameter, tombstoning every old alias of
that capability while preserving the concrete owner list and unrelated captures.
This supplies a resource-sensitive binding rule for actual App/Lam/Var nodes,
not a separate evaluator or an assumption that an arbitrary substitution is safe.

The runtime fragment still requires a direct lambda, an owned variable argument,
a closed one-cell Buffer annotation. The common judgment now has scalar and
owned result modes: returning the last capability preserves its live identity,
while releasing all other tracked resources. A fresh consuming continuation can
then receive that returned capability without reviving old lexical aliases.
This does not cover higher-order/partial application, general owned-producing
App arguments, or dependent Buffer lengths and result-type substitution. The
producer/consumer theorem composes their execution relations at a fresh
capability boundary. A recursive syntactic application extension now connects
that boundary to actual direct Buffer1 App/Lam nodes with an App-shaped owned
argument. The producer accounts for the entire current resource inventory,
returning one capability; the body receives only its parameter;
existing Types/Exec derivations supply the leaves. This does not justify
dropping captures or interpreting arbitrary open/dependent applications.
The next framed extension supports retained owner and scalar captures using an
explicit static prefix partition: the producer cannot access the reserved frame,
and the body cannot access consumed aliases. Frame preservation is derived from
execution and conservation, not a supplied untouched-trace premise. This closes
the singleton-body restriction for that checked partition, not arbitrary
partition inference/coherence, general closures or dependent substitution.
The framed judgment is now closed under the existing Free, allocation,
scalar/owned Lend, scalar-let and owner-binding continuations. Calls beneath
those constructors participate in the same totality, heap safety and accounting
statements rather than stopping at an opaque old derivation. Structural
expansion preserves the previous typing and execution on exact graphs; it does
not add new dependent types or eliminate the explicit partition plan.
A plan-free lexical execution bridge now separates that static proof plan from
the runtime meaning of the supported graph. Concrete captured owner/scalar
bindings remain in their lexical positions, including consumed aliases; the
static context revokes access instead of pretending the runtime deleted them.
Simulation into an independently deterministic lexical evaluator gives the
same value, exact events and final heap for any supported typed plan with the
same initial interpretation. Existing totality supplies execution, and safety
transfers to every plan-free execution of the fragment. This closes the
fixed-plan operational ambiguity, not partition inference or the remaining
dependent-language coverage gaps.
The first runtime-length extension now refines the existing uniform read-only
heap with exact object lengths and read indices. Open U64 index expressions
have lexical substitution laws; source Buffer/Ref annotations and Lt evidence
are interpreted against the same closing values. A sized source subset derives
allocation/read/free safety and dependent owner-result lengths. Its
closing-instance judgment is separate from the previous full Buffer1 fragment:
it does not yet generalize every framed call or owned-result Lend, arbitrary
nonuniform buffers, Store, or full dependent Pi/result substitution. The
checked example uses one graph across arbitrary runtime n/i inputs rather than
replacing n with constants in the graph.
The sized judgment now also supports direct owned transfer, framed owned
application and a restricted owned-result Lend whose fresh result length is
independent of the original buffer length. These rules participate recursively
in the same safe-execution and accounting theorem. Static prefix partitions
revoke producer/body authority without changing runtime lexical positions;
the plan-free evaluator remains deterministic. Retained captures preserve
their lengths and payloads. The reader is still specifically a fresh allocation
initialized by an in-bounds read, not an arbitrary effectful reader, and the
judgment remains semantic closing-instance typing rather than full dependent
Pi preservation.
Those remaining omissions remain part of the common-typing gap rather than
optional checker implementation refinement.

The sized composed fragment now also has a compact target syntax and runtime
whose values have no ghost constructor. A source-slot mask computes retained
indices; true comparison branches remove their proof binder rather than push a
placeholder. A fuel-bounded structural compiler checks both branches and
produces an erasure derivation on success. Constructive execution correspondence
in both directions preserves values, events and heaps, transferring the existing
typing-derived ownership guarantees. This is physical ghost-slot compaction for
this fragment, not erasure adequacy for every specified Core rule or a proof
that the production compiler emits this target. Whole-syntax coverage is an
explicit extra premise: closing-instance typing alone can constrain only the
branch taken by that instance.

## Required results versus existing evidence

| Original requirement | Existing result | Still needed for the original gate |
| --- | --- | --- |
| Dependent-rule stabilization | Preservation fixtures, rejection suites and targeted fixes | Continue source/Core audits; do not equate passing fixtures with a metatheorem |
| Consistency and pure preservation | Restricted pure dependent calculus; conversion, substitution, progress with explicit overflow | Cover the rest of the specified pure reductions and typing rules |
| Exactly-once ownership and borrow non-escape | Abstract quantity traces; guarded heap/lease invariants; restricted scalar and owned-result rules | The common specified typing-to-runtime ownership theorem described above |
| Erased values agree with pure values | Pure payload erasure, restricted lease-free heap correspondence, and physical ghost-slot compaction for the sized composed fragment | Coverage of the broader specified runtime grammar and its erasure association |
| Core lowering against Lean MIR semantics | Actual bounded MIR instructions/CFG semantics and conditional closed-pair validation | A lowering correspondence theorem for the required runtime fragment, not only supplied matching pairs |
| Published accepted-program guarantee | Individual scoped statements with trust boundaries | One release statement whose premises and covered rules actually satisfy the original gates |

Native checker, exporter association where used, MIR-to-LLVM, LLVM and runtime
assumptions must be stated. Native regression successes remain implementation
evidence, not replacements for missing proofs. The existing scoped results do
not yet justify describing the whole 0.6 Core or its executables as verified.
